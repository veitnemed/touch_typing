# Сборка для Windows

Готовый архив x64 содержит `TouchTyping.exe`, учебный движок, файлы старых маршрутов и два сценария запуска. После распаковки откройте `Start-Live.cmd` для Live или `Start-Workday.cmd` для старого курса «Рабочий день». Инструкции по клавишам есть в `START-RU.txt`.

Сборка из PowerShell выполняется через `package.ps1 -Version 1.6.0`. Для сборки под Windows из Linux нужен .NET SDK 10. Укажите новую папку в `windows/build-release.sh ПАПКА`, затем упакуйте её содержимое.

## Проверка на Windows

Проверьте Live на US и RU, выбор четырёх классов, связанные цепочки вкладок Chrome, палитры VS Code и учебного терминала. Chrome и VS Code заполняют учебную область и не требуют ручного набора адресов и имён файлов. В обоих режимах задания должны продолжать состояние сцены и завершаться по истечении трёх минут. Повторные сочетания с удержанием модификаторов должны засчитываться один раз на каждое нажатие основной клавиши.

Пробел запускает и продолжает паузу. Enter используется для действий в сцене. Ошибочная клавиша подсвечивается красным; подсветка, руки и клавиатура отключаются независимо. Для MateBook D16 в режиме мультимедиа F11 требует Fn+F11, а без Fn эта клавиша отправляет PrtSc. Режим Fn задаётся в подготовке занятия.

Alt+Tab, Alt+F4, PrtSc и Super должны действовать внутри активного учебного окна. После паузы, смены фокуса, завершения и закрытия клавиши возвращаются системе. Проверьте F8/F10 и показ альтернативной клавиши при конфликте с заданием. Уменьшите окно до 960×600 и проверьте подсказки. После полного подхода перезапустите приложение и проверьте рекорд.

Закрытие настоящего окна предлагает сохранить занятие и выйти. Отмена оставляет занятие на паузе. Alt+F4 внутри активного занятия относится к учебному окну.

Проверьте прежние упражнения, ввод Python, независимое скрытие клавиатуры и рук, редактор и запуск Start-Workday.cmd. Для нативной проверки нужен стенд Windows 10/11. Кросс-сборка в Linux проверяет компиляцию и упаковку.

## Автопроверка интерфейса

Запустите `Test-Live-UI.ps1` рядом с приложением. Стенд создаёт отдельный процесс `--qa`, проходит четыре класса и два режима, проверяет US/RU, сочетания, паузу, фокус и закрытие учебных окон. `-FullSession` включает проверку настоящего подхода на 180 секунд. `-Seed 7` задаёт воспроизводимый маршрут, `-OutputDirectory` выбирает папку отчёта. В ней сохраняются `report.json`, `windows-ui.log` и отдельный проверочный профиль. Для этого прогона нужен рабочий стол Windows.
