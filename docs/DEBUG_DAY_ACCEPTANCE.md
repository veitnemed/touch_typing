# «Разобрать ошибку без мыши»: проверяемый контракт

Два отдельных упражнения в разделе «Рабочий день»:

- «Разобрать ошибку без мыши · с подсказками»: `workday-debug-guided`. Проект расчёта цены, исходники `billing.py` и `factors.py`; ошибка умножения на 1000 вместо 100.
- «Разобрать ошибку без мыши · самостоятельно»: `workday-debug-independent`. Проект времени, исходники `clock_app.py` и `duration.py`; ошибка деления на 10 вместо 1000. Другая проверка, текст ошибки, справка и файл отчёта. Проход без раскрытия клавиши/ответа.

В каждом случае виртуальный терминал открыт с фактическим результатом первого запуска внутреннего профильного теста. Отладка выполняется на отдельном виртуальном проекте; ни команды, ни файлы ученика не исполняются и не меняются на компьютере.

| Действие | Положительная проверка | Контроль, который не должен пройти |
|---|---|---|
| Открыть редактор из терминала и поиск по проекту | Передано действительное сочетание (либо поиск приложения для неприкреплённого VS Code); `Ctrl+Shift+F`, запрос и Enter показывают место вызова из сообщения | Войти и выйти из поиска; открыть посторонний файл или совпадение |
| Открыть вызов, перейти к определению | Enter переносит каретку внутрь искомого имени; F12 открывает импортированный модуль, не одноимённый похожий файл | Другой жест, совпадение в строке или локальное имя |
| Свериться со справкой | В соседнем окне Chrome найден и выделен нужный текст; редактор по возвращении показывает ту же вкладку | Только открыть Chrome или найти другое значение |
| Исправить и сохранить | Алгоритм внутренней проверки читает сохранённый исходник, а не открытый буфер; использует конкретный тест текущего проекта | Несохранённая правка, неверный коэффициент, запуск чужого теста или подстановка вывода через echo |
| Снять окно, вставить в отчёт | Камера захватывает только активный виртуальный терминал с результатом теста; буфер содержит PNG, Ctrl+V добавляет ссылку на реально сохранённый бинарный артефакт в текущем виртуальном отчёте | Снимок браузера, всей сцены или до успешного теста; текстовый буфер; вставка в другой файл |
| Сохранить отчёт | Итоговая проверка читает запрошенный сохранённый Markdown, ссылку и связанный PNG; отчёт действителен только для актуального сохранённого исходника | Только показать картинку, правка без сохранения, повреждённая/чужая ссылка или изменённый исходник |

Автоматизация движка разделена с нативным тестом: проверяет обе раскадровки, отказ до исправления, отсутствие зачётов при смене контекста, изолированные имена файлов, неподходящие сочетания и итоговый артефакт. Отдельная нативная приёмка GTK/WPF должна подтвердить реальную доставку Alt+Print и фактическое изображение терминала. Если ОС перехватывает комбинацию, сценарий не выдаёт зачёт за обычный снимок экрана. Сгенерированная движком протокольная миниатюра, где используется, не предъявляется как нативный снимок.

Запуск приёмки: `PYTHONPATH=linux:linux/tests TOUCH_TYPING_ENGINE=/path/to/TouchTyping.Engine python linux/tests/test_debug_day.py`.
`linux/tests/test_debug_day_x11.py` принимает `TOUCH_TYPING_QA_DEBUG_MODE=guided|independent`. Используйте отдельные чистые `XDG_DATA_HOME`, `XDG_RUNTIME_DIR`, `TOUCH_TYPING_QA_OUTPUT` и собственный Xvfb с `-auth` (`TOUCH_TYPING_QA_XVFB_PID`, `DISPLAY`, `XAUTHORITY`, `GDK_BACKEND=x11`). Подтверждение разрешения от композитора в Xvfb подменено; все клавиши, включая Alt+Print, проходят сквозь GTK через XTest. Эта приёмка не подтверждает перехват сочетания на физическом GNOME/Wayland или клиентской Windows.
