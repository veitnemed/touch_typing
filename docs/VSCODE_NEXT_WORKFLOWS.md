# После перехода по месту ошибки: что добавить в Live / VS Code

Не менять маршрут выпуска .11: переход из traceback проверяется отдельной реализацией. Ниже план следующих двух рабочих приёмов, не зачёт готовых задач.

## 1. Выборочная замена в проекте: следующий практический срез

В текущей модели `Ctrl+Shift+F` уже показывает результаты поиска по проекту, а `Ctrl+H` делает замену внутри файла. Нет связки «увидеть все совпадения и исключить неподходящие перед правкой нескольких файлов». Это отдельный навык, а не повод повторить существующий поиск.

Рекомендую начать с маленького задания: два действующих профиля читают `https://old.example.invalid/v1`, архивная копия и диагностический пример также содержат этот текст. Пользователь находит только действующие конфигурации, смотрит diff минимум одного совпадения, исключает целый архивный файл и заменяет нужные две записи. В одном варианте похожий адрес (`/v10`) и строку комментария тоже нужно сохранить. Другие варианты могут менять не только имена, но и правило выбора: область `./live/**`, исключение конкретного файла либо одно совпадение из нескольких в одном документе.

Проверять **фактические три вещи**: какие строки вошли в готовый preview; какие пути и диапазоны действительно записались; что архив, пример и несвязанные несохранённые правки не изменились. Повторный запуск из незавершённого задания возвращает фокус, запрос, значения и исключения. При отмене/устаревшем совпадении не оставлять частично переписанные документы. Уровень можно начать с «Рабочие приёмы», добавить в обычную ротацию и сохранить доступ напрямую.

Не учить лишнему Ctrl+S после явной глобальной замены: [документация VS Code](https://code.visualstudio.com/docs/editing/codebasics#_search-and-replace) описывает предварительный diff и замену одного совпадения, файла или всей выдачи; [исходник сервиса Microsoft](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/search/browser/replaceService.ts#L104-L124) после применения пытается сохранить затронутые модели. Лучше финалом перечитать записанные конфиги или запустить связанный учебный тест. Для узкого пилота поддержать литерал + видимое исключение/простой glob; не обещать весь ripgrep, regex/замену групп или внедрять реальный доступ к машине.

## 2. Подсказка сигнатуры: второй независимый срез

Как минимум два разных инструмента: [Ctrl+Space открывает Suggestions; Enter или Tab вставляет выбранный вариант](https://code.visualstudio.com/docs/editing/intellisense), [Ctrl+Shift+Space открывает параметры вызова](https://code.visualstudio.com/docs/reference/default-keybindings). [Для Python реальный редактор использует соответствующее расширение и языковой сервер](https://code.visualstudio.com/docs/python/editing#_autocomplete-and-intellisense). Симуляция должна показывать предложения по фактическому имени, импорту и позиции курсора, не обещая поддержку полноценного Pylance.

Первый проход: в коротком Python-модуле есть похожие функции `load_reports`, `load_report` и `load_summary`, разные допустимые типы и параметр `limit`. Выбрать не первый вариант на автомате; применить его в реальном теле функции, открыть подсказку внутри вызова, правильно использовать обязательный аргумент и проверить конкретный результат. Для переноса — новая тема (не просто другое число), язык/названия и взаимный порядок вариантов, одна сигнатура без аргумента и отвлекающее похожее имя. Нажатие в терминале ничего не зачитывает. Esc не правит файл. Физический ввод в обеих раскладках и первые попытки без подсказки логируются отдельно от верного конечного кода.

## Почему эти два

Первая функция снижает риск массовой правки ненужных файлов, вторая экономит переключения к справке при незнакомом вызове. Это продуктовые гипотезы, не измеренная частота. [Эксперимент A crossover interaction](https://pubmed.ncbi.nlm.nih.gov/26651347/) поддерживает сравнение с освоенным мышиным путём после нескольких самостоятельных повторов, но срок/число повторов и ожидаемое ускорение из него нельзя переносить на этот тренажёр.

На старом `Ctrl+G` отдельный нюанс: [примечания Microsoft к VS Code 1.106](https://code.visualstudio.com/updates/v1_106#_go-to-line-improvements) описывают осмысленное ограничение номера за пределами документа до последней строки. Это не оправдывает старую ложную подпись «Строка 999» при реальной позиции на EOF. Даже при будущей реализации такого ограничения ошибочная исходная координата не должна получать зачёт, когда случайно попала в правильный конечный диапазон.
