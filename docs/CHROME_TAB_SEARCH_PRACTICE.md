# Live / Chrome: открытые вкладки и проверяемая ссылка

Обычная карточка Chrome по-прежнему начинает длинный маршрут. На уровне «Рабочие приёмы» в него добавлено «Найти открытый регламент и передать проверенный код». Из «Настроить» это же законченное поручение можно запустить напрямую. Старые уроки и предыдущие результаты не заменены.

В Chrome сочетание `Ctrl+Shift+A` открывает поиск по открытым вкладкам, `Ctrl+1…8` переходит на вкладку по позиции, `Ctrl+9` на последнюю ([официальная справка по вкладкам](https://support.google.com/chrome/answer/2391819?co=GENIE.Platform%3DDesktop&hl=en), [привязки Windows/Linux](https://support.google.com/chrome/answer/157179?hl=en)). В тренажёре поиск охватывает открытые вкладки текущего учебного окна и не читает настоящие вкладки, историю, аккаунты или другие окна Chrome. Название и URL видны в результатах. Enter переключает существующую вкладку, а не создаёт копию. Пустая выдача оставляет фокус в поле. Esc возвращает фокус в ранее активное поле или страницу.

В поручении открыто восемь вкладок. Поиск находит действующую, архивную и обзорную версии; ученик должен выбрать нужную. Затем он ищет в документе поле `control-code`, переносит точный адрес через буфер и записывает считанный код на «Листе сверки». Итог зависит одновременно от источника и значения. Нулевой префикс значим. Ошибочный архив, неправильная ссылка или другое значение не создают квитанцию. Верная пара сохраняется в виртуальном `source-review.txt` и видна в результате занятия. Три варианта по-разному расставляют похожие источники, меняют значения и номер итоговой вкладки. В самостоятельном режиме верхняя задача не выдаёт готовую комбинацию или контрольный код. Навигация мышью работает, но не засчитывает требуемое физическое сочетание.

Локальная проверка: `PYTHONPATH=linux:linux/tests python3 -m unittest test_chrome_tab_search` с собранным общим движком; `audit_live_course_rotation.py --app chrome` проверяет обычный маршрут обоих профилей. Нативные окна: `linux/tests/test_chrome_tab_search_x11.py` через Xvfb/XTest и `windows/Test-Chrome-TabSearch.ps1` с распакованным Windows EXE. Первый запускается с проектным X11 QA-окружением; второй требует отдельной интерактивной Windows-сессии. Совпадение профилей в тестах движка не заменяет запуск Windows-сборки.
