# Практическое поручение в терминале

Профиль в каталоге **Live** меняет учебную оболочку, а не систему компьютера. Для Ubuntu карточка «Терминал» открывает **Bash**, для Windows 10 карточка «PowerShell» открывает **Windows PowerShell**. В каждой оболочке по умолчанию одно законченное поручение из четырёх действий, без таймера и требования набрать 20 или 40 действий. Это базовые задания, а не три разных уровня сложности. Старые Bash-поручения остались в «Ubuntu → Терминал → Настроить» на обеих платформах. Незаконченные занятия продолжаются с того же шага, а черновики Ubuntu и Windows 10 не заменяют друг друга.

## Ubuntu: разбор журнала Bash

| Действие | Наблюдаемый результат | Когда проще интерфейс |
|---|---|---|
| `grep ERROR app.log` | Из известного журнала исключаются INFO/WARN. Старый сбой остаётся видимым; файл не меняется. | Один маленький файл проще открыть в редакторе и найти текст встроенным поиском. Терминал оправдан для повторяемого фильтра, длинного вывода и передачи выдержки. |
| `tail -f app.log` | Начальные строки видны, новые появляются последовательно. Новая запись действительно добавляется к учебному файлу. Приглашения командной строки пока нет. | Для разового чтения GUI проще. Для поступающих строк и остановки наблюдения без закрытия файла терминал полезен, если редактор не умеет следить за изменениями. |
| `Ctrl+C` | Прерывается наблюдение, а не служба и не приложение. На экране `^C`, вернулось приглашение. Стирание черновика не даёт этот зачёт; остановка до новой ошибки предлагает повторить. | Пауза/закрытие внутри средства просмотра удобны, но важно различать остановку просмотра и остановку фонового сервиса. |
| `grep ID app.log` | Из вывода нужно взять идентификатор именно новой ошибки. Валидатор получает реальные строки начала запроса и ошибки. Успешный grep старого ID не проходит. | Для одной строки легче обычный поиск. Сгруппировать несколько записей одной транзакции и передать точную выдержку удобно без прокрутки всего журнала. |

## Windows 10: разбор сбоя синхронизации

| Действие | Наблюдаемый результат | Когда проще интерфейс |
|---|---|---|
| `Select-String ERROR sync.log` | Из файла `sync.log` выводятся только совпадения, с именем файла и номером строки. Старая ошибка остаётся видимой. | Для одного короткого журнала поиск в редакторе проще. Терминал оправдан для повторяемого отбора с номерами строк. |
| `Get-Content sync.log -Wait` | Видны текущие и затем новые записи; они дописываются в файл примерно раз в секунду. `Get-Content sync.log` без `-Wait` читает только текущее содержимое и не зачтётся. | Для единичного чтения лучше GUI; наблюдение за растущим журналом полезно, когда редактор не следит за изменениями. |
| `Ctrl+C` | Останавливает только ожидание, возвращает приглашение `PS C:\Users\Student\Project>`. Остановка до новой ошибки не засчитывается; можно повторно запустить просмотр. | Кнопка остановки наблюдения удобна и в GUI. Здесь важно отличить остановку чтения от остановки синхронизации. |
| `Select-String ID sync.log` | ID берётся у новой ошибки. В записях видны начало конкретной попытки копирования и причина сбоя. Поиск ID предыдущей ошибки не завершает разбор. | Для краткого знакомства с файлом проще обычный поиск; для точной выдержки по попытке удобно видеть все совпадения и номера строк сразу. |

В каждой оболочке три варианта со своими предыдущим и новым ID, причиной и содержимым. Следующий разбор не повторяет предыдущий законченный случай той же оболочки. Данные генерирует сама симуляция. Учебные команды не запускают Bash или PowerShell, не читают и не меняют файлы компьютера; сам профиль занятий сохраняется как обычно. В виртуальном журнале реально меняются строки, фильтрация читает эти изменения, а пауза и новый запуск сохраняют место. В ветке PowerShell поддерживаются только нужные флаги двух команд и буквальные пути внутри учебного проекта; это не поддержка общего языка PowerShell, сценариев, конвейеров или всех поставщиков. В частности, `archive.log` доступен для чтения, но живой поток идёт только в `sync.log`.

Семантика PowerShell: [Select-String (Windows PowerShell 5.1)](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/select-string?view=powershell-5.1), [Get-Content, параметры Wait и Tail (5.1)](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-content?view=powershell-5.1).

## Что убрано из автоматической очереди

| Команда или приём | Причина |
|---|---|
| `whoami` | Имя уже показано в приглашении. Команда нужна в скрипте, на сервере или после смены пользователя, а не на каждом локальном старте. |
| `pwd` | Приглашение и путь файлового менеджера уже показывают контекст. Имеет смысл при неоднозначном пути, удалённом сеансе или проверке скрипта. |
| `ls`, `ls -l`, `ls -la`, `tree` | На обычном рабочем столе папку быстрее просмотреть в GUI. Оправданы списки для машинной обработки или проверка прав/скрытых файлов с конкретным вопросом. |
| `cd` и длинный путь | Для известной локальной папки быстрее открыть её в GUI; в стартовом стенде нужный каталог уже открыт. Осмысленно перед работой в другом проекте. |
| `Ctrl+R`, `↑`, `history` | Это повтор уже выполненной команды, не подмена её первого набора. Пустая история нового разбора не знает будущих целей. Упражнения на историю остались отдельно. |
| `id`, `uname`, `ps`, `ps aux` | Только когда важны владелец, права, версия системы или конкретный процесс. Системная информация и диспетчер процессов проще для разового осмотра. |
| `clear` | Меняет вид вывода, не решает рабочую задачу. |
| `cat`, `head`, статический `tail -n` | Для чтения документа GUI обычно удобнее. Полезны в конвейере или когда нужны конкретные строки, а не как обязательные остановки. |
| `find`, `sort`, `uniq`, `wc -l` | Оставлены для большого набора, точного отбора или подсчёта. До постановки такой цели не добавляют ценности. |
| `mkdir`, `touch`, `echo`, `cp`, `mv`, `chmod` | В первый разбор входят только чтение и остановка наблюдения. Файловые операции имеют смысл с настоящим переносом или защитой; единичные действия локально проще через GUI. |
| `git init`, `git status`, `git diff`, `git add`, `git commit`, `git log` | Отдельный сценарий работы с фактическими изменениями учебного репозитория. Не имитация диагностики журнала и не обязательный ритуал для заметки. |
| `reboot`, `shutdown`, `sudo`, `apt` | Обслуживание, не ежедневный ввод; отдельная цель, права и ответственность обязательны. Даже в симуляции это не привычный первый шаг. |
| `pytest -q`, сетевые команды | Не добавлялись для списка. Нужен стенд, где тест зависит от изменений проекта или запрос возвращает проверяемые данные. |

Семантика: [Ubuntu grep](https://manpages.ubuntu.com/manpages/noble/man1/grep.1.html), [Ubuntu tail](https://manpages.ubuntu.com/manpages/resolute/man1/gnutail.1.html), [GNU Bash: поиск по истории](https://www.gnu.org/software/bash/manual/html_node/Searching.html).
