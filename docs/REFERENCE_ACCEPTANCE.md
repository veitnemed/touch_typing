## Behavior / data bindings

- «Печать» opens typing courses. «Live» is the only catalog of work environments. Cards map to `LabCatalog.Apps`, with the desktop card reflecting the persisted Ubuntu / Windows 10 choice. Activating a card once by mouse or Enter starts its default first task, with no intervening catalog or settings. Preserve access to all exercises and utilities without third/fourth top-level sections.
- A compatible saved lesson has an explicit «Продолжить» action on its card. It resumes at the saved step; starting a new lesson must not silently delete an outstanding draft. Returning from a lesson or its result restores the same Live catalog and focus to the source card. Shared and OS-specific draft compatibility follows the existing engine rules.
- «Настроить» opens the selected environment’s wide two-column panel, using available space at both sides. Put exercise and difficulty on the left and guide mode, action limit and optional timer on the right; one «Начать» action stays reachable below. Keep the same neutral palette for closed and expanded controls. Verify a fully visible open timer, selection, hover, and keyboard focus at 1024×600; use responsive reflow or scrolling if needed rather than cropping fields. Do not recolor the recognizable interior of Chrome, VS Code or an OS simulation.
- Live hands and onscreen keyboard are independent, off by default on a clean or older profile, and remembered only after explicit changes. Resizing does not opt the user in. Both off removes the aid row instead of reserving blank space; changing a Live aid must not change Typing preferences. Retain the real color-coded keyboard and hands, enlarging enabled aids when there is usable room. The Live visual keyboard always shows QWERTY, regardless of the actual input source.
- On a Live goal that requires English text, physical RU input must not modify the target text, route progress or error count. Show «Переключи раскладку на EN», preserve the field and caret, and resume EN input after the real layout change. Do not switch the host layout for the user or block unrelated shortcuts, free Unicode typing, or explicit layout-switch training. «Печать» keeps its RU/EN behavior and grading. Remove redundant visible `[начало-пробел]` labels without removing the actual start behavior.
- One summary metric on both platforms: confirmed distinct catalog shortcuts / distinct applicable catalog shortcuts for current real layout; if using `liveSkills.confirmed`, document its evidence threshold. Unavailable history uses truthful zero/empty state. Do not seed production 42/18/27/35/10 or «Рекомендуем» badge merely to match the mock. A preselected Ubuntu and actionable recommendation are separate states; if no evidence, caption the intentional difference rather than simulate it. Captured comparable demo state can use isolated genuine fixture data if explained.
- Linux current paths `Studio.navigate`, `LabPage.describe/start`, `show_pause_modal`, result panel; Windows `App.ShowHome`, `BuildLabHome`, `StartLab`, `RenderLab`, `FinishLab`, `BuildLabResult`. New shell/layout must bind existing lesson/save/capture, not reproduce logic in UI. Respect OS compositor and keyboard behavior. If an apparent control is implemented as a status indicator, do not style or tab-stop it as functioning toggle; label unexplained/missing controls in comparison.
- Task panel must split title, help and status; long help scrolls/collapses without replacing entry. Visible distinct focus/selection/caret and error feedback must not rely on color alone. Input must return to previous target after modal/sidebar dismiss; do not steal lesson input through newly added shortcuts.

### Compact lesson and selected line breaks

- Since preview.4, the standalone module-title strip is intentionally absent during a lesson. Reclaim that height for the work surface; keep the goal, shortcut, accessible progress and scenario name, and lower controls. Home and the catalog keep their own navigation. This is an explicit exception to the practice-header landmark above.
- In the editor, selecting a line break paints one cell after the last glyph of that row. A selection ending before the line break paints no such cell. Reversing the same selection changes the active caret end, not which characters are selected. Don't add a fake marker at end of file.
- Check the editor as two layers: the engine's selection/replacement/clipboard offsets and the rendered visible range. The GTK selection-render check and WPF `--check-live-render` use controlled multiline states with Cyrillic, a combining mark and an emoji. LF/CRLF in those render fixtures validates drawing, not the Live editor's ability to import CRLF. Snapshot checks do not substitute for actual keyboard input, compositor behavior or client Windows DPI testing.
