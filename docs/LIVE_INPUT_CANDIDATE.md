# Live: приёмка первого среза после v1.7.0

**База:** опубликованный тег v1.7.0, commit `721a2ed44e6e8914f4c295656de212982015664f`.
**Статус:** инженерный кандидат, не новый релиз. Проверка движка, отрисовка, ввод в окно и испытание на физической клавиатуре учитываются отдельно.

## Что воспроизвелось на v1.7.0

Повторено на опубликованном Linux x64 архиве с совпавшим SHA-256 через протокол движка. В отдельном терминале и встроенном терминале VS Code при одиночных нажатиях:

| Раскладка | После Home, →, → | После Delete | После Backspace |
| --- | --- | --- | --- |
| EN | `ab|cde` | `ab|de` | `a|de` |
| RU | `аб|вгд` | `аб|гд` | `а|гд` |

Delete в конце и Backspace в начале сохраняют текст. Повторный keydown удерживаемой ← не двигает каретку; это воспроизведённый дефект, а не подтверждение любой жалобы на одиночное нажатие. Символ `|` в таблице обозначает позицию каретки. Физическая клавиатура Windows в проверке базы не участвовала.

## Критерии первого среза

| № | Что проверять и как | Что не закрывает эта проверка |
| --- | --- | --- |
| 01 | Оба терминала, обе раскладки: шаги из таблицы, границы строки и удаление выделения. Сверять строку, координату и кадр. | Тест движка не подтверждает доставку событий обеими ОС. |
| 02 | Удерживать ← и Delete на длинной строке; удерживать Enter на готовой команде; отпустить Ctrl в другом окне и продолжить обычный набор. | Синтетический повтор не подтверждает задержку и поведение физической клавиатуры. |
| 04 | В задании Chrome на Ctrl+L: Alt+D выделяет адрес, но не увеличивает счёт; после возврата в страницу Ctrl+L даёт ровно один зачёт. Проверить посторонний контекст и видимую подсказку. | Этот сценарий не заменяет аудит всех сочетаний и всех режимов. |
| 05 | В VS Code открыть Ctrl+F, ввести запрос, нажать Esc, продолжить набор с прежней каретки и снова открыть поиск. Встроенный терминал: ↑ обращается к истории команды, а не редактора. | Полная матрица фокуса всех модальных окон остаётся отдельной работой. |
| 14 | На 1366×768 открыть подсказку в середине длинной команды и продолжить; проверить видимость рабочей строки, контроля паузы и завершения. | Голая сцена WPF или тест модели не проверяют целое окно. |
| 15 | В длинной строке пройти начало, середину и конец; сравнить каретку, видимое выделение и реально удалённый диапазон. Проверить Ctrl+F, EN/RU и многострочное выделение. | Проверка цвета или ширины поля не заменяет приёмку Unicode, переносов и масштабов. |
| 49 | Отдельно протокол, рисование, автоподача клавиш в открытое окно и физическая клавиатура. Проверять именно собранный архив, фиксировать ОС, раскладку, SHA и вид ввода. | Windows Server CI не считать клиентской Windows 10/11. X11 не считать Wayland. |

Изменения первого среза не меняют путь профиля и не требуют сброса данных. Полную миграцию с v1.7.0 на обеих ОС проверять отдельно в задаче 47; тесты выполняются на отдельных учебных профилях.

### Следующие срезы

1. **Связный рабочий эпизод:** задачи 07–09 и одна сквозная миссия 29. Принять только после точного сравнения содержимого файла и буфера, перезапуска и повторной проверки артефакта. Зафиксировать совместимость старого профиля (47).
2. **Расширение моделей и обратной связи:** 03, 06, 10–13, 16–28, остаток 29 и 30. Сначала поведение и сохранность, затем оформление.
3. **Адаптация и перенос навыка:** 31–40. Самостоятельные успехи и подсказки учитывать раздельно. Результаты добровольных участников не заменять синтетическими.
4. **Платформа и выпуск:** 41–48, оставшиеся проверки 49 и внешний пилот 50. Не обозначать Windows как проверенную до прогона из архива на нужных клиентских ОС и физическом ноутбуке.

### Локальные результаты

Проверены Linux x64 (Debian 13, .NET SDK 10.0.100): 344 общих проверки, 1 001 проверка Live, 7 041 проверка терминала, стресс-сценарии (90 сеансов, 160 602 события), 24 протокольных теста, 51 сквозной маршрут на движке из архива, 3 теста геометрии отрисовки и Node-проверка состояния редактора. Windows x64 кросс-сборка демонстрирует сборку WPF и упакованный движок, а не работу на Windows. Тест старого браузерного черновика проверяет сохранение уже полученного зачёта после перехода на новую логику Ctrl+L.

Нативные проверки для готовых пакетов запускаются workflow `live-input-candidate.yml`, который не публикует релиз. На Windows доступны отдельные артефакты запуска WPF и UI Automation/SendInput. На GNOME Wayland локальный запуск: `./check.sh --terminal-only --output ./typing-check-results`. Физические Windows 10/11, парные кадры и видеозапись не засчитаны по результатам протокольных тестов.
