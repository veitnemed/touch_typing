# Live: проверка результата одного поручения

Только `workday-report` («Доставить отчёт и проверить правку»), локальный кандидат. Команда `head -n 2 spectrum-report.txt` по-прежнему показывает первые две строки. Для зачёта движок дополнительно сравнивает **всё сохранённое содержимое** отчёта в проекте с эталонным учебным результатом и проверяет, что исходника больше нет в «Загрузках». Если первые две строки совпали, а файл повреждён ниже, этап не засчитывается; игрок получает объяснение.

Ответ `lab-state` для этого этапа содержит `reportArtifact`: виртуальный путь, содержимое и признак исходника. До зачёта результата нет. Результат доступен пока проверенный файл остаётся неизменным в текущей сцене; это не запись в архиве всех поручений. Другие маршруты, формат профиля, клавиши и экраны не изменены.

Проверки: штатный сквозной маршрут, намеренное изменение третьей строки без изменения вывода команды, повторное появление исходника в «Загрузках», восстановление корректного файла и получение результата. Физическую клавиатуру Windows и полноценную миграцию профиля эта проверка не покрывает. Это часть задачи 29, а не её закрытие.

Совместимость сохранений: при восстановлении записи, созданной до отметки `@strict-report`, движок воспроизводит уже пройденный шаг по прежней проверке первых двух строк. Это сохраняет позицию и историю без повторного зачёта. Если отчёт не соответствует новой проверке, `reportArtifact` при этом не появляется. Для новых действий действует строгая проверка, а после сохранения граница правил переживает перезапуск. Непомеченные профили промежуточной сборки GitHub Actions неотличимы по формату записи от профилей опубликованных версий и трактуются как старые. Переход проверен с учебным профилем, записанным Linux-движком v1.7.0; это не подтверждает перенос всех данных или запуск на клиентской Windows.
