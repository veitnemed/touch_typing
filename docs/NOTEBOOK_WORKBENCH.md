# VS Code: блокнот и проводник в учебном проекте

Редактор выбирает представление по открытому документу: .py остаётся редактором исходников, а .ipynb открывается блокнотом внутри тех же вкладок и дерева проекта. Палитра показывает команды движка для текущего документа. Сервер, установленный Python и сторонние ядра тренажёру не нужны: работает явно обозначенное учебное ядро.

Внешнее поведение сверяется с [Jupyter Notebooks in VS Code](https://code.visualstudio.com/docs/datascience/jupyter-notebooks) и [управлением ядрами VS Code](https://code.visualstudio.com/docs/datascience/jupyter-kernel-management). В тренажёре есть одно учебное ядро. Его меню показывает доступный вариант и поддерживаемые команды, а не предлагает подключить несуществующие серверы. Сохраняется оформление GitHub Dark Default.

| Состояние | Действие | Наблюдаемый результат |
|---|---|---|
| Вкладка .ipynb, выбран контейнер | Enter / Esc | Редактирование рисует рамку и каретку; при возврате каретка скрывается, остаётся полоса выбранной ячейки. |
| У видимой code-ячейки | Щелчок по треугольнику слева | Выбрана и выполнена именно эта ячейка. Номер запуска и результат остаются при её исходнике. |
| Ядро занято | «Прервать» | Очередь прекращается, уже вычисленное остаётся. Перезапуск сбрасывает ядро, но не содержимое документа. |
| Длинная ячейка или traceback | Колесо / PageUp/PageDown; Shift — влево/вправо | Видны другие строки и правая часть длинного кода. При правке прокрутка следует за кареткой. |
| Ячейка Markdown | Enter, правка, Esc | Снова показаны заголовки, списки, цитаты или текст. |
| Фокус в блокноте или дереве | Shift+F10, ↑/↓, Enter, Esc | Доступно контекстное меню области с рабочими командами. Esc закрывает его без правки документа. |
| Explorer проекта | Открыть строку, создать папку, переименовать, перенести | Используются канонический учебный путь и буфер. При конфликте имени сохраняются поле и данные. |

Мышь и контекстное меню работают с учебным состоянием, но не засчитывают задачу на конкретное физическое сочетание. Вычисление, проверка конфликтов и отмена принадлежат движку. Клиент хранит только прокрутку и открытое меню. Восстановленный документ прокручивается к сохранённой ячейке и каретке.

## Повторяемая приёмка

- До изменения: v1.9.0-preview.6, Live → VS Code → «Исправить формулу в блокноте по заявке», .py → блокнот → старый и новый вывод → сохранение ответа. Старый вид показывал до трёх строк ячейки и одну строку вывода, без работающей панели.
- После изменения: тот же маршрут проверяют test_editor_notebooks_x11.py и Test-Live-UI.ps1 -NotebookMission. Это проверка сохранности прежнего навыка, а не доказательство новых функций.
- Для новых функций запустите linux/tests/test_notebook_workbench_native.py из готового архива через чистый Xvfb/XTest стенд. В Windows используйте windows/Test-Notebook-Workbench.ps1 -Application <распакованный TouchTyping.exe> -OutputDirectory <новая папка>. Скрипты открывают поручение из каталога и отправляют клавиши и клики в реально отрисованное окно. Кросс-компиляция и искусственные изображения не доказывают оконного прохождения.
- На каждой платформе приложите исходный .ipynb, снимки в командном режиме и при правке, ошибку и прокрутку. Укажите реальные размеры и масштаб. Не засчитывайте недоступные 125%/150% либо физическую клавиатуру.
