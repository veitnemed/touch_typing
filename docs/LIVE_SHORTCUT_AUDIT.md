# Аудит клавиш Live и Huawei MateBook D16

## Что проверено

Базовая версия: `0e4494b34a20ad83cdabe804d413c7ab157c0bb7`.
Ниже перечисляются сочетания встроенных упражнений Live. В стартовый
набор входят 144 действия общего каталога, 20 действий рабочего стола
Windows и 17 действий отдельной миссии редактирования Python. После
удаления пустой подсказки и повторов это 112 уникальных строк жестов
по умолчанию. Пользовательские сочетания, профили привязок GNOME,
позиции в доке, настройки управления приложением, отдельные занятия
«Горячие клавиши» и печать спецсимволов в эти 112 не входят.

На чистом профиле C#-движок прошёл опубликованные маршруты с seed=0:
66/66 в профиле Ubuntu (1 486 шагов с жестом) и 50/50 в профиле Windows 10
(1 027 шагов с жестом). Итого 116 маршрутов, 2 513 шагов с жестом и 101
различная строка жеста. Это проверка игрового движка: ввод по протоколу,
переход каждого шага и отсутствие ошибок на каноническом маршруте.
Она не доказывает доставку событий оконной системой и не является
измерением на физическом MateBook. Две симуляции рабочего стола и
две нативные платформы (GTK и WPF) — разные оси проверки.

### Остальные 11 строк: целевые проверки

Эти строки не встретились как заданные жесты в проходе 116 маршрутов.
Дополнительный прогон `LabCatalog.Resolve → LabScene.Apply` на той же
версии прошёл 12/12 контекстов для всех 11 строк (дважды для Ctrl+G).
Эти проверки не используют обработчики окон. В таблице также перечислены
более полные ручные или нативные сценарии, которые полезно повторить.

| Жест | Минимальная проверка |
| --- | --- |
| `Alt+B` | В терминале перевести курсор к началу предыдущего слова; строка неизменна. |
| `Alt+F` | В терминале перевести курсор к концу следующего слова; строка неизменна. |
| `Alt+Shift+Tab` | На трёх открытых окнах выбрать предыдущее; активировать лишь после отпускания Alt. |
| `Ctrl+-` | В Chrome уменьшить масштаб 100% → 90%; не путать с раскладкой и клавишей на цифровом блоке. |
| `Ctrl+2` | После разделения VS Code переключиться во вторую группу и проверить вкладку. |
| `Ctrl+G` | В Chrome перейти к следующему совпадению; в VS Code открыть переход к строке, ввести номер и проверить позицию. |
| `Ctrl+K` | Удалить хвост команды от курсора; `Ctrl+Y` восстанавливает именно удалённое. |
| `Ctrl+R` | В терминале найти свою недавнюю команду, не запуская её до Enter; в Chrome обновление не меняет URL. |
| `Ctrl+Shift+B` | В Chrome показать/спрятать панель закладок; запись закладки остаётся доступной в менеджере. |
| `Ctrl+Shift+C` | Скопировать выделение из учебного терминала, не меняя строку; затем вставить в отдельное поле. |
| `Ctrl+Shift+P` | В VS Code открыть палитру; выбрать команду и проверить результат, Esc оставляет документ без изменений. |

## Найденные отклонения в базовой версии

- «Рабочий день», шаг `file-home`: `Alt+NumPad7` не открывает домашнюю
  папку и даёт ошибку. В воспроизведении зачёт остался на 24, ошибки 0 → 1.
  Стандартный `Alt+Home` на том же шаге проходит.
- Chrome, шаг `next-tab`: `Ctrl+PageDown` переключает вкладку и ошибочно
  даёт зачёт за строго заданное `Ctrl+Tab`. В воспроизведении зачёт 22 → 23,
  ошибок 0. Альтернативная команда может оставить полезное действие, но
  не должна заменять требуемый навык, как уже сделано для `Alt+D` рядом
  с `Ctrl+L`. Дополнительно проверить `Ctrl+PageUp` против
  `Ctrl+Shift+Tab`.
- При исправлении правил зачёта не считать прежний ошибочный ввод заново:
  проверить восстановление черновика с историей нажатий до изменения.

## MateBook D16: маркировка и границы проверки

Huawei относит MCLF к MateBook D 16 SE 2024, Intel Core 12-го поколения.
Для соответствующего семейства Huawei документирует, что при выключенном
Num Lock цифровой блок даёт навигационные команды по нанесённой легенде.
Поддержку отслеживать с учётом маркировки `7/Home`, `1/End`,
`9/PageUp`, `3/PageDown`, `8/↑`, `2/↓`, `4/←`, `6/→`,
`0/Insert`, `./Delete`. Клавиши верхнего ряда и клавиши цифрового блока
это разные физические позиции. `5` не заменяет стрелку, `NumEnter` и
арифметические клавиши не следует автоматически приравнивать ко всем
обычным сочетаниям. Поддержка второй легенды применима к контекстному
шагу навигации, не к упражнениям верхнего цифрового ряда и не к обычному
текстовому вводу. Включённый Num Lock и обычную цифру вне такого шага
нельзя лишать её исходного значения.

- GTK: `linux/platform_linux.py` получает физическую позицию GDK/XKB.
  В базовой версии один и тот же keycode передаётся как `NumPad7`
  независимо от `KP_7` / `KP_Home`. На нативном уровне Wayland
  необходимо разрешение перехвата GNOME; проверить получение, отказ,
  потерю фокуса и повторный захват отдельно от движка. Не менять реальные
  настройки рабочего стола и не имитировать системный запуск команд.
- WPF: `LiveStudio.ScanKey` отличает обычный и extended scan.
  Не-extended `0x47` из цифрового блока распознаётся как `NumPad7`,
  extended Home остаётся Home. Нативный тест использует `SendInput`
  с обоими сканами; Num Lock настраивается до занятия или при паузе
  (активный учебный перехват может его подавить). Проверить отсутствие
  зависшего модификатора после паузы и ухода в другое окно.
- Fn: Huawei подтверждает режим приоритета F-клавиш при активном
  индикаторе Fn на своих Windows-ноутбуках. Сторона Alt/Ctrl/Super,
  факт появления конкретного F-события, комбинация `F11/PrtSc` и
  системный перехват на конкретной ОС не устанавливаются по одному
  каталогу модели. Проверять программные события без обещания, что
  мультимедийный режим физической клавиатуры уже протестирован.
- Порядок прогонов: оба профиля симуляции × GTK и WPF, затем
  EN/RU для физических сочетаний, левый/правый модификатор в общих
  сочетаниях и неверная сторона в заданиях на конкретный модификатор.
  Для Alt+Home отдельно нужны обычный Home, `NumPad7` при обоих исходных
  состояниях Num Lock, Alt+7 сверху (не зачёт) и одинокий NumPad7
  вне навигационного шага. В отчёте отмечать источник события.
