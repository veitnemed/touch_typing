# Какие привычки стоит тренировать в TouchTyping

Аудит 25 ноября 2026. Исходный профиль: повседневная работа в Linux/Windows с Chrome и проектами в VS Code, а не все компьютерные пользователи.

## Доказательства и границы

- **Замер:** опубликованное наблюдение или эксперимент с указанной выборкой. Замеры действий не следует выдавать за частоты конкретных сочетаний.
- **Документация:** подтверждает применимость и эффект в данной среде; не распространённость.
- **Продуктовый приоритет:** измеряем ценность рабочего результата, перенос на новый материал, стоимость ошибки и преимущество над интерфейсом. Не выдаём эвристический порядок за рейтинг всех пользователей.
- **Покрытие:** отдельно обычная карточка, ручной выбор и продолжение. Переименование и повтор одного упражнения не расширяют курс. Порядок в каталоге не равен необходимости тренировать действие регулярно.

## «Рабочий день»: сверка с фактическим курсом

- **Источники и версии.** Маршрут verified-bulletin уже соединяет Chrome, закладку, историю, фактический CSV действующей версии и редактирование заметки. Не добавлять вариацию «заново скопируй ссылку и сохрани». Выделяем как дальнейший проверяемый пробел работу с существующей записью: восстановить утерянную закладку, заменить только устаревшую ссылку и оставить остальную заметку без изменений.
- **Загрузки, файловый менеджер и редактор.** Доставка по фактическому пути и чтение нужной записи уже проверены. Новое дело оправдано, если помогает разрешить конфликт, узнать правильный файл или перенести навык на два соседних источника; один и тот же сценарий под новым названием не считаем прибавкой.
- **Контекст при прерывании.** Пауза и повторный вход должны сохранить конкретный файл и состояние. Для повторения поменять активное начальное окно и материалы, а успех сравнивать по результату: не перепутаны окна и тот же сохранённый объект отработал дальше.
- **Расследование сбоя.** В курсе уже существуют log-config-repair с правкой рабочего файла, неизменным архивом и повторным тестом. Разнообразие нужно по дефекту и способу поиска, а не через дополнительные синтаксические команды без эффекта.
- **Снимок и передача.** Полезен, когда снимок передаёт проверяемый факт. Урок, который создаёт снимок только для зачёта и больше ничего с ним не делает, не стоит регулярно повторять.

### Как проверять ценность новых повторов

Для каждого предложенного навыка: исходная рабочая цель → что реально изменилось → GUI-альтернатива → что лучше клавиатурой → новая ситуация → измерение. В двух сопоставимых случаях записать успешность первого самостоятельного решения, активное время, подсказку, точность результата и сохранность исходников. Повторить после нескольких дней на другом материале; не сравнивать скорость RU со скоростью EN и не начислять зачёт за событие, не доставленное ОС. Пилот у 5–10 добровольцев даёт сигнал для продукта, а не статистику всех пользователей. Не собирать аппаратные события вне учебного окна и не включать фоновую передачу действий.

## Почему популярное в терминале не всегда стоит делать обязательным

- [Исследование публичных псевдонимов команд, Empirical Software Engineering](https://doi.org/10.1007/s10664-021-10036-y): изучено более 2,2 млн определений alias с GitHub; среди ведущих команд были `cd`, `git`, `ssh`, `ls` и `vim`. Здесь посчитаны определения в конфигурациях, а не вызовы. Выборка смещена к людям, которые настраивают свою оболочку и публикуют настройки. Это повод сохранить продвинутую практику для разработчика, но не основание заставлять обычного пользователя повторять `ls`.
- [Greenberg, реальные трассы 168 пользователей csh](https://grouplab.cpsc.ucalgary.ca/grouplab/uploads/Publications/Publications/1988-UsingUnix.Report88-333-45.pdf). Это независимая историческая точка для проектировщиков командного интерфейса; выборка и оболочка из другой эпохи. По ней нельзя вывести рейтинг команд для современных Ubuntu и PowerShell.
- [Voronkov, Martucci и Lindskog, SOUPS 2019](https://www.usenix.org/conference/soups2019/presentation/voronkov): из 300 опрошенных администраторов именно в работе с межсетевыми экранами 60% предпочитали GUI и 32% CLI. Это не общий рейтинг оболочек. Но выбор интерфейса зависит от цели даже у специалистов.

| Поручение | Куда направить ученика | Решение |
|---|---|---|
| Открыть одну знакомую папку, найти загрузку, скопировать один файл | Файловый менеджер: поиск, область поиска, имя и тип файла | Не повторять `ls`, `pwd` и `whoami` в обычной терминальной тренировке. Не маскировать эту работу под команду из истории. |
| Разобраться, почему сбой повторяется, пока другой процесс дописывает журнал | Терминал: найти записи по признаку, увидеть новую запись, остановить чтение и выделить её ID | Обычная карточка; короткая практическая связка для Bash и PowerShell, с разными входными данными. Оценивать нужный результат, а не число команд. |
| Проверить конкретный тест и перейти от сообщения к исходнику | VS Code: терминал или панель тестов, исходник по строке, повтор того же теста | Дополняет обычный маршрут редактора. Не требовать полного повторного ввода длинной команды, если известна команда из урока. |
| Увидеть, что именно сейчас попадёт в Git-коммит | VS Code Source Control для визуального сравнения; `git diff --staged` для разработчика, который уже ведёт работу в терминале | Оставить ручной продвинутый выбор. Сравнивать, что действительно попало в индекс; голый вывод статуса не учебная цель. |
| Перезапустить свой компьютер | Видимое действие ОС, если нужен один перезапуск | Знать `reboot` можно; делать его обязательным повтором смысла нет. Реальный хост из упражнения не перезапускать. |

## От анализа к дополнениям обычного курса

Здесь «новая проверка» означает наблюдаемый результат обычной карточки, а не отдельный режим или команду ради команды. Идентификаторы сценариев, тесты и уровень платформенной приёмки перечисляются в заметках соответствующего выпуска.

| Сфера | Навык, на который делаем ставку | Проверяемый связный результат |
|---|---|---|
| Печать | Смена языка при наборе сообщения с числами, путём и латинскими именами | Короткая рабочая записка коллеге напечатана дословно. Сравнивать точность и активное время на другом равнозначном материале, а не на той же строке из памяти. |
| Chrome | Поиск среди похожих вкладок и возвращение к источнику после отвлечения | Выбран действующий документ, не архив и не черновик. Адрес и нужный фрагмент принадлежат выбранной вкладке; новая навигация не подменяет старые упражнения. |
| VS Code | Восстановить контекст по сообщению об ошибке | Из сообщения открыта нужная строка, исправлено только значение в рабочей конфигурации, тот же тест снова запущен, архив не менялся. |
| Ubuntu и Windows | Ограничить поиск нужной папкой, отличить утверждённый документ от черновика и проверить копию | Конечный путь и содержимое копии совпадают с исходным нужным файлом. Выбор и папка сохраняются после прерывания. Команда соответствует выбранной среде. |
| Терминал | Прочитать живой источник и найти конкретное событие, а не печатать текст для зачёта | После остановки наблюдения работает приглашение и найден точный новый идентификатор события. История команд остаётся ручным навыком. |
| Рабочий день | Восстановить точную секцию источника и исправить уже существующий материал | Меняется только старая ссылка; новый адрес сохраняется и открывает раздел в новой вкладке. Пауза и перезапуск не теряют подготовленную замену. |

**Что не измеряли:** частоту команд у Ивана или у пользователей TouchTyping, экономию времени от этих конкретных уроков и процент удержания навыка через неделю. При проверке полезности лучше предложить парные задачи «через GUI / любым способом», сменить исходные данные и сравнить результат и время. Частоту применения спрашивать отдельно от того, помнит ли участник название клавиши.
