# Приёмка TouchTyping 1.9.3

Точка отсчёта: опубликованный v1.9.2. Новые задания дополняют существующий курс. Ни прохождение движка, ни количество записей в каталоге не заменяют прохождение обычного маршрута в окне приложения.

| Область | Что нужно подтвердить | Доказательство |
| --- | --- | --- |
| Запуск | Из обычного меню начать и продолжить «Печать» и Live, вернуться назад и снова начать. Для завершившегося и зависшего движка сохранить уже записанный черновик. При невозможности запуска показать ошибку, не переотправлять действие без явного повторного запуска. | Linux: тест живого, но не отвечающего процесса. Оконные испытания Linux и Windows: отдельно. Похожий симптом не доказывает причину сбоя у пользователя. |
| Сочетания | Подсказка указывает физическую клавишу и палец; оба Alt, автоповтор, правильный контекст и раскладка. Для комбинированного Win+Alt проверить полный аккорд и каждую комбинацию с пропущенным модификатором. | Разделить реальное окно, стенд, устройство и поведение ОС. Не угадывать сочетание, вызвавшее старое окно распознавания речи. |
| Печать | Два результата по разные стороны границы 98% выглядят различимо; допуск в работу над ошибками считается по неокруглённой точности. Один курс исправления на попытку, с восстановлением. | Исходные счётчики, текст интерфейса и наличие кнопки при обеих точностях. |
| VS Code | В обычной практике доступны прежние навыки и новые операции с выделением, вставкой, перестройкой и проверкой кода. Цель называет файл, символ или действие в текущем контексте. | Пройти из карточки, затем через свободный выбор и сохранение. Отдельно проверить движение вверх/вниз, неверную цель, конфликт и следующий полезный шаг. |
| Git в VS Code | Состояния рабочей копии, индекса и последнего учебного коммита различимы; дифф и действие относятся к выбранному файлу. | Поменять два файла; подготовить нужный, снять подготовку, заново подготовить и зафиксировать. Второй файл должен остаться изменённым, но не попасть в коммит. Не обращаться к настоящему Git пользователя. |
| Bash и PowerShell | Команда полезнее ручной операции в конкретном повторяемом сценарии, а не просто короткая. Сбоку есть понятное, сворачиваемое объяснение. У TXT-проверки одинаковый смысл в настоящей оболочке и симуляции. | Сравнить с Files/Explorer на одинаковых исходных данных; отметить, измерено ли время и известно ли, как часто действие встречается. Доказать вывод в файле и совместимость со старым черновиком. |
| Chrome и Проводник | Устранены видимые расхождения затронутых состояний, собственные и системные элементы не путаются. | Парные кадры GTK/WPF с обычного входа. Проверить активное и неактивное состояние, 1024×600 и взаимодействие с клавиатуры. |
| Длина Live | Полный обычный маршрут не заканчивается после одного короткого поручения. Целевой минимум: 30 осмысленных действий без искусственного наполнения; явно выбранное самостоятельное поручение сохраняет свой естественный конец. | Зафиксировать фактические шаги и достигнутый результат для каждой карточки и профиля ОС. |
| Выпуск | Точный SHA; проверки сборок Ubuntu GTK/X11, Ubuntu GNOME Wayland, Windows Server WPF; регрессии и проверка SHA-256 публично скачанных архивов. | Ссылки на точный прогон, архивы и измерения. Физический MateBook засчитывать только после фактической проверки. |
