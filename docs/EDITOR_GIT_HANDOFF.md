# VS Code: передать результат, а не просто выучить Ctrl+C

**Вход.** Live → VS Code запускает прежний чередующийся курс; обе новые задачи входят в обычный выбор своего уровня. Чтобы открыть конкретно их: Live → VS Code → Настроить → средний уровень, «Собрать инструкцию дежурному…», либо продвинутый, «Собрать рабочую конфигурацию…». Выбор поручения не выставляет лимит основному курсу.

| Было в 1.9.2 | Добавлено | Как понять, что получилось |
|---|---|---|
| Сбор заметки, восстановление файла, изменение расчёта, поиск определения, передача вывода, ноутбуки и дерево проекта | Из расписания и рабочих заметок выбрать по две строки и вместо двух старых фрагментов собрать инструкцию; личный телефон и архивная запись остаются только в источниках | Открыть diff `handoff.md`: заменены ровно две секции. Оригиналы источников не переписаны. |
| Умение выделить строку или перенести файл | Из проверенного шаблона и личного черновика собрать `delivery.ini`; перенести только нужный блок, сохранить остаток черновика | В результате содержатся точные параметры и контакт текущего варианта, не старые метки. Остаток личного черновика не попал в коммит. |
| Панель показывала diff рабочей копии, но не создавала локальный коммит | Снять ненужное изменение с подготовки, посмотреть обе стороны diff, подготовить только итоговый файл, ввести своё сообщение, зафиксировать | Один коммит виден в `git log --oneline`; `git status --short` показывает только личную правку. Нет удалённого репозитория, сетевой отправки или доступа к файлам пользователя. |

Shift+F10 открывает меню выделенного изменения, Enter вызывает **Stage Changes** или **Unstage Changes**. Shift+Tab переводит фокус из списка в поле сообщения, Ctrl+Enter подтверждает коммит. Вне проверяемого поручения доступны кнопки +, − и Commit. Списки и терминал читают один индекс. Для подготовленного файла сравниваются HEAD и индекс, для неподготовленного — индекс и рабочая копия. Это учебное подмножество [Source Control в VS Code](https://code.visualstudio.com/docs/sourcecontrol/staging-commits): здесь нет сервера, синхронизации, расширений или заявления о полном паритете с VS Code.

**Проверки.** `test_editor_git_release.py`: два поручения × три набора исходных данных × два профиля платформы. Проверяет действительное содержимое файлов и источников, пустое и произвольное сообщения коммита, закрытие процесса и восстановление индекса, содержимое журнала и статус. `test_editor_course.py` проходит обычную карточку и все миссии по уровням. `test_editor_git_release_x11.py` вводит реальные оконные события XTest после выбора из карточки. `windows/Test-EditorGitRelease.ps1` предназначен только для наблюдения настоящего WPF-окна с изолированным профилем на интерактивной Windows; кросс-компиляция не доказывает прохождение этого теста.

**Какая строка, файл или ячейка?** Задания палитры символов, поиска по проекту, списка вызовов и быстрых исправлений называют строку из того списка, который открыт на экране. Переименование в проводнике показывает путь файла. Для выбора и редактирования ячейки блокнота видны номер, тип и начало её фактического содержимого. Проверка `test_editor_objective_names.py` сравнивает цель с реальной строкой/ячейкой в шести поручениях; названия не привязаны к одному случайному примеру.

Визуальный ориентир панели — [официальный снимок Stage Changes](https://code.visualstudio.com/assets/docs/sourcecontrol/staging-commits/stage-changes.png). Для тренажёра использована GitHub Dark Default: поэтому основная кнопка зелёная (`#238636`), а не синяя, как на иллюстрации темы VS Code по умолчанию. Свежий обычный прогон GTK показывает центральную кнопку, значок Source Control с количеством файлов, счётчики групп, действие +/− перед буквенным статусом и разницу HEAD ↔ Index. Не изображены полное контекстное меню, подготовка отдельных строк и удалённая синхронизация.
