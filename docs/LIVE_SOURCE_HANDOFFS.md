# Сверка источника и передача результата

Работа идёт в учебной среде на локальных данных. Сайт, CSV, журнал, редактор и
файловый менеджер используют одно состояние миссии. Сеть, файлы пользователя
и установленный Python/Jupyter не нужны. Под «Windows 10» ниже понимается
профиль симуляции; физическую Windows подтверждает только Windows-прогон.

## Что добавлено поверх v1.9.0-preview.6

| Рабочий день, Рабочие приёмы (Ubuntu, Windows 10) | Старые доставка CSV, подготовка заметки и отладка не заменены | Сверить редакции, перенести URL в черновик, вернуться к источнику из закладки, перевести скачанный отчёт из «Загрузок» в `project/reports`, взять строку из этого файла и сохранить заметку. |

Поручения доступны из настройки карточки по указанному уровню. В обычной
практике это дополнительные дела соответствующего уровня/профиля, а не замена
стартовых поручений. Обычный запуск, явный выбор и восстановление черновика
проверяются независимо. Возврат в миссию переигрывает события; вместе с номером
шага должны восстановиться окна, разделённые вкладки, позиция ввода, локальные
файлы и содержимое буфера.

## Как проверять результат, а не наличие записи в каталоге

### Бюллетень, файл и заметка

1. **Исходное состояние:** учебный поиск, версии с одним и тем же ключом и
   разными значениями. **Цель:** предъявить действующую запись. Поиск страницы
   приводит к бюллетеню; `Ctrl+F` и `Ctrl+G` отличают простое упоминание
   кода от настоящей строки таблицы. Та же операция в архиве даёт другое
   значение. Проверка учитывает URL версии и диапазон найденной строки.
2. **Проверка источника:** закладка хранит действующую версию, история позволяет
   вернуться к ранее открытому документу после просмотра архива. Сохраняется
   конкретный URL, не «последняя вкладка». На уровне «Рабочего дня» URL
   переносится в документ; этот черновик остаётся открытым при возвращении
   через закладку за CSV.
3. **Данные:** формат CSV содержит тот же ключ и версию файла. Загрузка меняет
   виртуальный диск. В «Рабочем дне» команда «Показать в папке» фокусирует
   ровно этот файл, перенос создаёт `reports/<название>-<версия>.csv` и
   убирает исходный путь из «Загрузок». Архивный файл имеет другие байты и
   должен остаться нетронутым.
4. **Итог:** VS Code открывает реально перенесённый CSV. Скопированный диапазон
   строки вставляется в заметку вместе с ранее введённым URL. Изменённый
   источник, не та строка или несохранённый текст не дают зачёта.

### Вернуться в нужное окно

В стартовом состоянии есть рабочий черновик с выделением поля и другое окно
VS Code с заметками. Файл на втором окне не является целью. Окна ставятся
рядом с утверждённым источником; редактор можно свернуть, чтобы прочитать
источник и перенести его с экрана/на другой стол. Восстанавливается именно
нужное окно, не просто приложение с таким же названием. Вставка заменяет
только выделенный маркер; соседние строки и файл второго окна не меняются.
Проводник/Files открывает сохранённый файл по действительному пути.

### Журнал вместо браузера

Рабочая настройка не проходит проверку (например, неверный разделитель
выгрузки, тайм-аут или выбран черновой CSV). Диагностика в терминале
показывает рабочий путь и причину. В журнале есть строка для исправления:
она находится в VS Code и переносится через буфер в точное место файла.
Встроенный учебный тест читает реально сохранённую настройку и архивную
копию: до исправления или при правке архива тест завершается ошибкой.
Это проверка учебной файловой системы, а не исполнение чужого кода.

## Прогоны

- `PYTHONPATH=linux /usr/bin/python3 linux/tests/test_source_handoff.py`:
  разные исходные данные, оба профиля, фактический URL, путь, байты и
  фокус; неверный ввод и контекст, перезапуск движка посреди черновика.
- Распакованная GTK-сборка, свежий профиль, X11 и физические коды XTest:
  `linux/tests/test_source_handoff_x11.py`. Скрипт открывает реальные
  карточки и меню «Настроить»; отрабатывает путь через открытые окна.
  `TOUCH_TYPING_QA_VIDEO=1` удерживает важные состояния для записи.
- На WPF повторить по тем же меню и результатам, отдельно указав ОС,
  масштаб, сборку и способ ввода. Профиль Windows в Linux-прогоне и
  успешная сборка Windows-архива не заменяют запуск WPF.

Для проверки обычного пути из того же меню выбрать «Последовательная
практика» (не название поручения), профиль Windows 10 и уровень «Рабочие
приёмы», без лимита. Режим `TOUCH_TYPING_QA_SOURCE_MODE=course` этого же
оконного прогона включает проверку границы. Новое дело следует за старым;
после подтверждения файла занятие продолжается, а новый результат не
перезаписывает сохранённый перед ним исходник.

Для внешней проверки WPF запустите из исходников
`windows/Test-LiveSourceHandoffs.ps1` с `-Application` на EXE из
распакованного архива и `-OutputDirectory` на новую папку. В обоих профилях
скрипт проходит настоящее окно с нативным вводом; в QA-режиме читает фокус,
каретку и контрольные суммы открытого, сохранённого и записанного текста.
