# Терминал: чему стоит учить регулярно

Решение по курсу TouchTyping, 25 ноября 2026. В приоритете пользователь Linux и Windows с обычным рабочим столом, который иногда работает с проектом в VS Code. Для системного администратора, удалённого сервера и программирования круг команд разный. Возможности команды подтверждены справкой; справка не доказывает, что пользователь выполняет её ежедневно.

## Фильтр для каждого действия

1. **С какой повторяемой целью человек пришёл?** «Ввести команду», «посмотреть имя» и «открыть историю» не цели сами по себе. Должен существовать вопрос, правка или проверяемый артефакт, которого человек ещё не получил.
2. **Почему здесь терминал, а не приложение с интерфейсом?** Для открытия, копирования или просмотра нескольких локальных файлов по умолчанию выигрывает графический сценарий. Для точной фильтрации большого журнала, проверки отдельного теста и текстового вывода, который нужен следующему действию, терминал может выиграть. Если VS Code решает весь сценарий естественнее, урок относится к VS Code.
3. **Что нужно помнить?** Короткую повторяемую часть набирают сами. Путь, имя сервиса, ключи или имя теста можно прочитать, выбрать или скопировать из контекста. Длинные команды показывать при необходимости, а не заменять набор обязательным Ctrl+R.
4. **Что подтвердит успех?** Результат меняется при смене данных. Нельзя сдать задание одним совпадением с подготовленной строкой. Повтор без подсказки получает другой файл, другую ошибку/строку, процесс или тест. Следующий шаг использует нужный результат.
5. **Безопасность и перенос.** Только виртуальные файлы и процессы. Общий курс не приучает к sudo, перезапуску и массовым операциям вслепую. Не преподавать Linux-команду как переносимую в PowerShell или наоборот: там, где у человека это разные команды, показываем разные профили.

## Разбор фактического каталога

| Действие | Нужно на постоянку человеку с GUI? | Решение |
|---|---|---|
| `whoami` / `id` | Нет. Реальная причина появляется при неверной учётке, контексте удалённой сессии или ошибке доступа. | Убрать из обычной ротации, не повторять в адаптивной. Можно оставить справку/разовый инцидент и восстановление старого урока. |
| `ls` / `ls -la` / `tree` / `find` | Для простого просмотра рабочего проекта рядом с Files/Explorer или VS Code обычно нет. В удалённом окружении или пакетном поиске бывают полезны. | Не основной курс. Сохранить ручной технический сценарий с фильтром и конкретным найденным объектом; без искусственного `apt install tree`. |
| `pwd` / `cd` | Не упражнение само по себе. Однократно проверяет нужную рабочую папку, если тест/утилита берёт относительный путь и окружения отличаются. | В контексте одного инцидента, когда неверная папка реально меняет результат; не требовать в начале каждой миссии. |
| `clear` / `history` / ↑ / Ctrl+R | Не рабочий итог. ↑ полезна после опечатки и повторе; Ctrl+R нужен при длинной истории, не когда команда короткая и видна. | Компактная помощь и отдельный ручной сценарий редактирования длинной команды. Не подставлять Ctrl+R на место набора. |
| `ps` / `uname` | Не нужно регулярно пользователю с System Monitor/«О системе». Смысл в воспроизведении несовместимости или в удалённой среде. | Справочная диагностика; не список заданий «собрать информацию». |
| `reboot` / `shutdown` | Может понадобиться, но повторение перезапуска как навык без причины не нужно. На домашнем ПК есть меню. | Вне обычного курса. Только моделировать явно объяснённое обслуживание и не запускать на системе. |
| `mkdir`, `touch`, `cp`, `mv`, `chmod` | Одно ручное копирование, переименование или создание папки проще в Files/Explorer. Пакетное действие, строго выбранные пути и доступ могут оправдать оболочку. | Не обычная начальная ротация. Сохранить старые технические маршруты вручную. `chmod` только с явным конфликтом доступа, не «600 по привычке». |
| `cat`, `head`, `tail`, `wc`, `sort`, `uniq`, `echo`, конвейеры/вывод | Просмотр двух строк можно делать мышью. Для извлечения воспроизводимого результата из большого файла бывает существенная польза. | В основном курсе только когда следующий шаг читает полученный фактический вывод/сводку. Не тренировать набор слов или ключей отдельно. |
| `grep ERROR app.log` / `Select-String ERROR app.log` | Да в конкретном повторяемом деле: длинный текстовый журнал, нужно отделить сбой от нормальных строк и указать его причину. Не универсальная ежедневная привычка. | Первый кандидат для короткой практики без админ-прав. Передать подтверждённый код/строку в учебную заметку. Другой набор данных должен менять ответ. |
| Ctrl+C для реально текущей команды | Да для пользователя терминала. Останавливает только работающую foreground-команду; не равняется копированию. | Короткий связанный шаг после запуска учебного потока; вернуть приглашение и использовать диагностическую строку. Если потока нет, отдельный обязательный блок не нужен. |
| `pytest -q` / `python -m pytest …` | Кандидат для пишущего Python пользователя; один короткий тест может дать более точный результат, но зелёный значок Test Explorer иногда проще. | В VS Code/Рабочем дне: воспроизвести сбой конкретного теста, исправить файл, проверить снова на отличающихся данных. В основной терминал попасть только после сравнения путей, без обязательных длинных строк. |
| `git status --short` / `git diff` | Git UI подходит для обычной работы. Короткая точная проверка без GUI полезна в удалённой рабочей копии, по пути, индексу или при передаче текстового результата. | Вариант для разработчиков в контексте review; не обучать установке Git/созданию пустого репозитория/слепому `git add .`. |
| `apt …` / `sudo …` | Нет как постоянный навык для обычного desktop. Эскалация и установка существенно меняют среду. | Не основной. Только прозрачная детерминированная симуляция в отдельном разделе, если есть реальная цель. |
| `df -h`, `journalctl -u …`, `curl -I …` | Условные кандидаты: заполнен нужный том, сбой конкретной службы, различаются HTTP-редирект и ответ на проверяемом адресе. Обычный локальный GUI нередко проще. | Не внедрять для заполнения каталога. Принять только после добавления ситуации, проверяемого результата и честного сравнения с GUI. Не запускать реальную сеть и команды пользователя из симуляции. |

Для варианта «в отчёт ушла неверная цифра» удержание навыка проверяется новым журналом, в котором другая неисправность. Вариант без реального преимущества терминала должен перейти в приложение, где он полезен, либо не войти в основной курс. Все прежние *полезные* рабочие действия остаются доступны вручную; существующий черновик открывается на старом шаге, а не принудительно пересоздаётся. Приёмка сравнивает не количество карточек, а фактические действия по обычному пути, в ручном выборе и при восстановлении старого профиля.

### Различие Linux и Windows для первого сценария

Bash: короткие `grep ERROR app.log` и `tail -f app.log` работают в каталоге урока. PowerShell: `Select-String ERROR app.log` и `Get-Content app.log -Wait` не обязаны быть столь же коротки. Если нужен только просмотр файла, длинная версия проигрывает графическому интерфейсу и не является отдельным повтором; задача с действительно текущим потоком и конкретным результатом оправдывает режим. Варианты запускаются только в учебной оболочке.
