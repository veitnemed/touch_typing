# VS Code: починить расчёт заказа и проверить изменения

1. В Live откройте «VS Code → Настроить → Рабочие приёмы → Исправить порядок и пересобрать блок расчёта → Начать».
2. В checkout.py опустите строку return total ниже трёх присваиваний. Заголовок функции и отступы не меняются. Сохраните первый этап правки.
3. В Source Control откройте локальный снимок: M отмечает изменённый checkout.py, а цветные строки показывают старый и новый текст. Ничего не публикуется.
4. Верните фокус к коду. Выделите только fee и total, затем замените выделение предложенным расчётом. Сохраните отдельную строку return.
5. Сохраните версию: checkout_total(4, 3) == 14, checkout_total(1, 0) == 2. Побочные файлы не должны изменяться.
6. Откройте test_checkout.py, найдите вызов checkout_total(4, 3), запустите два теста в терминале учебного проекта, сохраните их вывод в checkout-test.txt и откройте этот файл в редакторе. Итог должен быть «Ran 2 tests», затем «OK». Полное поручение состоит из 32 содержательных действий.

В обычных поручениях VS Code новое занятие вместо перемещения объявления Python восстанавливает порядок пунктов в release-check.md. Черновик, созданный этим этапом в 1.9.1, продолжает исходную работу в прежнем файле.

Стрелки в палитре выбирают команды, но не выполняют их. В связанных упражнениях проводник показывает точный путь, например incoming/warehouse-count.csv: Ctrl+X применяется к выбранной строке дерева, а не к открытому тексту. Это важно, если файл уже открыт и вкладка активна.

Отдельное поручение не меняет старые маршруты или их сохранённые позиции. Проверка GTK: linux/tests/test_editor_checkout_x11.py через изолированный X11 с компилированным движком и пустым профилем. Раннер использует обычные аппаратно-подобные события XTest; этот прогон не доказывает работу под GNOME Wayland или Windows.
